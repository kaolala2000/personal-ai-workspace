# 知识进化闭环 · 捕捉与治理协议

## 何时自动捕捉（不需要用户说“保存”）
一次协作满足任一条件即在任务结束时生成结构化记录：
- 做出了业务决策或明确结论（定价、选品、投放、达人、直播、SOP 变更等）
- 用户表达了判断、假设或经验总结
- 比较了多个方案并说明取舍
- 产生了可复用的方法、口径或模板
- 一次执行/复盘得出了与预期相同或相反的结果

普通闲聊、无结论的探索、重复确认不记录。

## 每条决策记录的固定字段
问题与背景 / 参考的历史资料与数据（来源链接或记录 id）/ 用户观点与假设 /
我的分析与不同意见 / 比较过的方案 / 最终决定与原因 / 预期结果与关键指标 /
验证条件与 verify_by 日期 / 后续回填的实际结果。
对应 loop.py 的 decision 记录正文模板，元数据必填：source、date、status、links。

## 进化规则
1. 新增前先查重（loop.py add 自动提示相似记录）：判断新/补充/修正/反证，
   用 links 关联，不重复建记录。
2. 被新证据推翻：新记录照常建，用 supersede 标记旧记录（原文保留），
   冲突双方证据与适用条件都写进新记录正文。
3. 假设只能进 hypotheses（pending_verification），验证后 resolve 为
   verified/refuted，禁止直接写进 facts。
4. 同一方法被验证 >=2 次：提炼为 sops 记录（status 先 draft，用户确认后 active）。
5. 事实进 facts 的条件：有来源证据（文档/数据/已验证复盘），注明适用市场与时间。

## 复盘机制
- 每条待验证记录必须带 verify_by。定时任务（cron: knowledge-loop-review，
  每周一约 09:00）运行 review 清单，只汇报到期未验证项，不自动改状态。
- 新数据到达（用户提供、同步程序更新、对话中出现）时，由我在当次对话中
  对照原判断 resolve 并说明差异。

## 红线（不自动写入）
密钥/凭证、私人敏感信息、未经授权的第三方公司资料、无法确认来源的数字。
涉及重大知识修正（推翻用户既有核心结论）先在对话中提示用户确认再 supersede。

## 与飞书/ima 的关系
本闭环库是“协作产生的新知识”的主存储（本地持久化）。飞书/ima 是历史资料源，
只读同步进来后在 knowledge/ 下做卡片，卡片与闭环记录通过 source 字段互相引用。
后续如需回写飞书/ima，须用户另行授权写权限，默认不回写。
